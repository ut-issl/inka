# inka — Web UI

Web UI が保つ不変条件。Web UI は 2 つの面を持つ 1 つのアプリケーションであり、他のすべての出力と同じ
共有モデルの上に成り立つ。**レビュー面**では承認者がレビューキューを辿り、`inka review` と同じように判断を
記録する。**グラフ面**では論証全体を探索する。
英語版(正): [English](https://www.space.t.u-tokyo.ac.jp/inka/design/web-ui/)

## 基盤

- Web UI は共有の論証ビュー(他のすべての出力と同じ投影)と、core がそこから導くレビューキューを表示する。
  論証をパースせず、ハッシュもレビュー状態もキューの順序も自分では計算しない。それらは `inka review` と
  `inka eval` が読むのと同じものを、サーバ経由で core から受け取る。
- サーバは自前の状態を持たない。すべての応答はリクエスト時点のリポジトリのファイルから導くので、ページと
  コマンドラインがプロジェクトの内容について食い違うことはない。`check` に通らないプロジェクトは診断として
  表示し、部分的な論証としては決して表示しない。
- Web UI が変更できるのは承認ログだけであり、それもレコード 1 件の追記に限る
  (後述「判断の記録」節を参照)。論証・値・証拠・既存のレコードを編集するものは Web UI 内に存在しない。
- 論証は DAG である。各ノードはグラフに 1 回だけ現れ、複数の親を持つノードは辺で表し、複製しない。
- 描画は決定的: 同一性と順序はビューのソート済み block-ID 順とキューの順序に由来し、同じリポジトリ内容は
  常に同じページを描く。
- 実装: レンダラは単一の TypeScript フロントエンドバンドル(`web/`。これらの不変条件の唯一の実装)であり、
  `inka serve`(Rust)が配信する。グラフライブラリはバンドルにベンダリングされ、inka の一部ではない。

## 局所ビュー

局所ビューは、両方の面がノードを提示する単位である。承認が束縛される対象(`concept.md` コア観念 2)であり、
したがってレビューする人が読むものである。

- ノードの局所ビューは次の順に表示する: ブロックへのコメント、description、証拠への参照、直接の子の
  description(それぞれその子要素へのコメントを添える)、期限注釈。各プロパティにはそれに付着したコメントを
  添える。これは `inka review` が出力する内容と順序である。
- 判断の対象である description は、周囲の子の description から視覚的に区別する。
- それより深いものは表示せず、その場で展開もしない: 子は description としてのみ現れる。子の下を読むには、
  その子自身の局所ビューへ移動する。
- ビューハッシュに入るものはすべて、ホバーもクリックも入れ子の枠内のスクロールもなしに画面に出ている:
  操作を介してしか読めない契約内容を作らない。
- ヘッダは対象(`<mode>:<id>`)とそのレビュー状態を示す。状態は必ず文字で書き、色はそれを繰り返すだけで、
  色だけに状態を担わせない。

## 契約テキスト

- description は CommonMark として描画する。コメント・id・証拠ターゲットはプレーンテキストである。
- 描画は契約内容を隠さず、変えない。description 内の生 HTML は解釈せずテキストとして表示する。外部リソース
  は読み込まない: 画像は代替テキストとリンク先として表示し、リンクは行き先を表示する。
- description のソース(ハッシュ計算の入力である、展開・正規化済みのテキスト)は描画から 1 操作で確認でき、
  Markdown が畳む空白や改行も検分できる。
- 論証由来のテキストを実行することはなく、CommonMark を超えるマークアップとして信頼することもない。制御文字
  と双方向オーバーライド文字は `inka review` と同じく無害化する。

## レビュー面

- キューは `inka review --list` が出力するものと同じ: 同じ対象を、状態(未承認 / stale / decline 済み /
  blocked)ごとにグループ化し、各グループ内で葉から上へ並べる。
- セッションは判断を受けられる対象(未承認と stale)を、キューの順に局所ビュー 1 つずつ辿る。decline 済みと
  blocked の対象は、何が解決するかを添えて一覧に示し、判断の操作は出さない。
- stale の対象には以前の内容を承認した人を、decline 済みの対象には decline した人を示す。
- レビューする人は承認・decline・スキップができる。キュー内の任意の対象を直接開くこともできる。キューの順序は
  推奨であって関門ではない。
- 進捗(キュー内の位置と残り)は常に見えている。

## 判断の記録

ブラウザで記録した判断は、`inka review` が書くレコードそのものである: 同じフィールド、同じファイルに、同じ
コード経路で追記する。レコードから両者を区別することはできない。

- **オプトイン。** 記録の機能は、サーバを承認者つきで起動したとき(`inka serve --as <approver>`)にだけ
  存在する。承認者なしのサーバは書き込みを行うルートを一切持たず、Web UI は全面的に read-only である。
- **同一性はサーバが決める。** 承認者と key id はサーバ起動時に固定する。ページは誰として記録するかを常に
  表示し、それを選ぶことも変えることもできない。
- **ループバックのみ。** 記録するサーバはループバックアドレスで待ち受ける。それ以外のアドレスでの記録の
  要求は起動時に拒否する。
- **自分のページからのみ。** 判断は、このサーバがこの起動中に配信したページからのものだけを受け付ける。
  同じブラウザで開いている別のサイトがレコードを書かせることはできない。
- **画面上のハッシュ。** 判断は、表示されていた局所ビューのビューハッシュを名指す。サーバは、それが今も
  対象の現在のハッシュである場合にだけ記録する。そうでなければ何も書かず、ページは現在の内容を表示する。
  ページを開いている間に行われた編集が、見られないまま承認されることはない。
- **局所ビューの全体。** 承認と decline は、判断を受けられる対象の、全体が表示された局所ビューの上でだけ
  提供する。それ以外の場所(グラフのカード、一覧の項目、ホバー)に、何かを記録する操作はない。
- **decline には理由が要る。** decline にはコメントが必須で、承認にはコメントを付けてもよい。
- **追記専用。** 1 つの判断は 1 つのレコードを追記する。レコードの撤回・編集・削除は提供しない。

## グラフ面

- すべてのノードはカードであり、モード・id・レビュー状態と、局所ビューと同じ描画の description を載せる。
  長い description はカード上で切り詰めてよい。全文はそのノードの局所ビューが示す。
- 4 つの discharge モード(objective / structure / bind / fiat)は視覚的に区別でき、カード上に名前でも
  示す。
- レイアウトはトップダウンの層状 DAG — objective が最上位、辺は下へ流れる。辺は親から各子へ向かい(矢頭は
  子側)、すべての辺は同じ太さで描く。
- `children:` の要素にコメントがある辺は、コメントがあることを示す。コメント自体は親の局所ビューで読む。

### 探索

- グラフは折りたたまれた状態で開く: objective とその直接の子が見えている。
- 子を持つノードは個別に展開・折りたたみできる。展開は直接の子を表示する。折りたたみは、展開されて見えて
  いる別のノードからは到達できない子孫をすべて隠す。
- 折りたたまれたノードは、隠れた子があることと、その下にあるノードの数を示す。黙って隠すものはない。
- ノードが見えるのは、それが objective であるか、展開されて見えているノードの子であるとき、かつそのとき
  に限る。ノードが見えるかどうかは、展開した順序に依存しない。
- グラフ全体を 1 操作で展開でき、また折りたたみ直せる。
- 別の場所(検索結果、キューの項目、局所ビュー内のリンク)からノードを表示させると、objective からその
  ノードまでの経路を展開する。

### 選択

- カードの選択で、そのノードの局所ビューをグラフの横に開く。グラフはそのまま残る。ノード用の 1 親等グラフは
  別には設けない: 局所ビューがノードの拡大表示である。
- 局所ビューはノードの親を補足的なナビゲーションとして列挙し、承認が束縛される内容とは区別して置く。
- Esc、または空白の背景のタップで、選択を解除する。

## 補足情報

レビューする人の助けになるが、承認が束縛される対象には含まれない文脈。局所ビューの契約内容とは常に視覚的に
分けて示す。

- **サイドバー。** どちらの面でも、サイドバーがレビューキューと論証の全ノードを一覧し、id と description の
  テキストでノードを検索できる。項目はノードのモードとレビュー状態を示し、選ぶとそのノードを開く。
- **ホバー。** ノードへの参照(局所ビュー内の子、親、サイドバーの項目、切り詰められたカード)のホバーで、
  そのノードのモード・id・状態・description をプレビューする。プレビューが判断の操作を出すことはなく、
  プレビューでしか読めないものもない。
- **namespace。** ノードの namespace は、ノードを名指すすべての箇所で id とともに示す。namespace 解決が
  入るまで、ノードの namespace は論証ファイルの stem とする。
- **面どうしのリンク。** レビュー面の局所ビューからグラフ上の位置を示せる。グラフで選択したキュー内の
  ノードはレビュー面で開ける。

## 不変条件ではないもの

- 色、カードの寸法、カードが切り詰めるまでに表示する行数、間隔、ズームの挙動、サイドバーのレイアウト、
  キーボードショートカットは表示パラメータであり、自由に調整する。不変条件ではない。
